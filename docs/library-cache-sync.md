# 음악 라이브러리 캐시와 기본 동기화

## 적용 범위

서버 없이 동작하는 기본 동기화를 구현한다. Google OAuth 권한은 기존 `drive.file`과 파일 선택 범위를 유지한다. Docker, SSE, WebSocket, 서버 즐겨찾기 동기화는 포함하지 않는다.

## 기존 동작과 새 정책

기존 전역 Query `staleTime=30초`는 캐시 삭제 시간이 아니다. 오래된 Query가 다시 활성화되면 목록을 재조회할 수 있었다. NAS의 SQLite `pages`는 서버 요청 실패 후 fallback으로 읽었으며, 앱 재시작 직후 저장 목록을 먼저 보여주는 경로는 없었다. 저장형 클라우드 Provider는 별도의 Store와 마운트 단위 요청 공유를 사용했다.

이제 라이브러리 Query는 재진입 자체로 네트워크 재검증을 시작하지 않는다. 목록을 사용하는 활성 화면의 공통 실행기가 다음 정책을 적용한다. 일반 설정이나 재생 화면은 음악 목록의 자동 조회 소비자가 아니다.

| 데이터 | 정책 |
| --- | --- |
| NAS·Drive·S3·MYBOX·Jellyfin 곡 목록 | 전체 검증 후 15분 |
| Drive 변경 목록 | 5분, 선택된 파일만 처리 |
| 서버 플레이리스트 목록·상세 | 해당 화면에서 5분 |
| 앨범·아티스트·검색 | 공통 곡 목록에서 계산, 별도 서버 요청 없음 |
| 로컬 폴더·좋아요·플레이리스트·설정 | 기존 로컬 저장과 즉시 반영 |
| 재생 대기열 | 기존 저장·복구 유지 |

라이브러리 메모리 Query는 60분간 보존한다. 그 이후나 앱 재시작 시에도 SQLite 스냅샷을 복원할 수 있다. 백그라운드 및 마지막 목록 소비자 해제 시 타이머와 목록 요청을 정리하며, 재생·다운로드 요청에는 영향을 주지 않는다. 자동 메타데이터 보완은 이미 확보한 목록만 구독한다. 사용자가 설정에서 곡 목록을 명시적으로 펼치는 화면은 목록 소비자로 처리한다.

## 저장 데이터와 일관성

- 기존 `music-library.db/pages`를 유지하고 `library_snapshots` 테이블을 추가한다.
- 키는 스키마 버전·Provider·계정 범위·선택한 라이브러리/파일 목록으로 구성한다. 세대 번호는 실행 중 응답 검증에 사용한다.
- 한 스냅샷에 전체 원본 곡 목록·전체 검증 시각·선택적 Drive cursor/태그 재시도 ID를 저장한다. 앱 표시 정보·숨김·앨범아트 패치는 기존 Store에서 적용한다.
- SID·인증 헤더·토큰·비밀번호·재생 URL은 저장하지 않는다. 원격 이미지 URL은 제외하고 NAS 표지는 현재 세션으로 복원한다.
- 페이지 캐시와 스냅샷 쓰기를 직렬화한다. 스냅샷과 cursor는 SQLite 단일 트랜잭션으로 저장하고, 도중 취소·계정 변경·쓰기 실패 시 rollback한다.
- NAS의 기존 100곡 페이지는 offset·total·길이·ID의 일관성이 확인되는 전체 목록만 복원한다. 검증 시각은 0으로 두어 온라인 재검증 대상으로 처리한다.
- NAS 연결 설정에서 캐시를 지우면 NAS의 새 스냅샷도 제거하며 다른 Provider의 스냅샷은 유지한다.
- NAS 복원은 저장된 계정 범위를 먼저 열고, 네트워크 오류로 SecureStore 연결을 삭제하지 않는다. 실제 세션 만료는 기존처럼 연결을 만료시킨다. API 경로·버전은 비밀정보 없이 별도로 최대 24시간 캐시하며, 없으면 discovery를 공유해 다시 확인한다. 처음 업그레이드한 기기가 오프라인이면 기존 페이지에서 곡 목록은 복원할 수 있지만 원격 표지·스트리밍은 API 정보와 네트워크 복구가 필요하다.

## Provider별 지원과 제약

### NAS

현재 검증된 `Song.list` v3는 전체 목록을 100곡씩 순차 조회한다. 페이지마다 total 변경·중복 ID·누락을 검사하며, 오래된 fallback이나 불완전한 결과를 정상 전체 스냅샷으로 확정하지 않는다. 곡 수가 같아도 제목·태그 등이 바뀔 수 있으므로 총개수만으로 변경 없음 판정을 하지 않는다.

현재 확인한 API에서 신뢰할 수 있는 전체 라이브러리 revision을 확보하지 못했으므로 15분 전체 재검증을 사용한다. 미확인 필드·조건부 요청을 추가하지 않았다. 페이지 확대·병렬화는 별도 작업이다. 수동 새로고침은 1곡 확인 요청 없이 전체 조회를 한 번 실행한다.

### Google Drive

기존 `drive.file` 권한으로 `changes.getStartPageToken`과 `changes.list`를 사용한다. [Changes API 공식 권한](https://developers.google.com/workspace/drive/api/reference/rest/v3/changes/list), [파일별 접근 범위](https://developers.google.com/workspace/drive/api/guides/api-specific-auth).

전체 기준 목록을 읽기 전에 cursor를 확보한다. 변경 페이지를 끝까지 처리하고 선택된 파일만 재조회·태그 보완하거나 삭제한다. 선택하지 않은 파일은 자동으로 추가하지 않는다. 변경이 없는 곡 객체·배열은 재사용한다. 태그 읽기 실패 ID는 다음 변경 조회에서 재시도한다.

cursor가 사용할 수 없으면 전체 조회로 복구한다. 변경 API가 거부되면 추가 OAuth 권한을 요구하지 않고 15분 전체 조회를 유지한다. 정상 변경 조회를 사용해도 15분 전체 조회를 안전망으로 실행한다. 로컬 문서 URI의 기존 접근·복구 경로는 유지한다.

### 기타 Provider와 오류

S3·MYBOX·Jellyfin은 기존 조회·인증 Store를 재사용하고 전체 스냅샷 복원을 연결한다. 필수 Provider 계약을 유지하며 Drive에만 선택적 `sync.revalidate`를 제공한다. 동일 Provider·계정·선택 조건의 조회는 공유한다.

자동 실패 재시도는 1→2→4→8→15분이고 수동 새로고침은 대기 시간을 건너뛴다. 인증·권한 오류는 반복 폴링하지 않는다. 실패해도 이전 목록과 오류·재시도 상태를 유지한다.

## 삭제와 재생 보호

현재 곡과 이전 재생 이력, 로컬 다운로드 곡은 보존한다. 현재 위치 이후의 삭제 확정 원격 곡만 대기열에서 제거하므로 현재 인덱스·위치·재생 엔진을 바꾸지 않는다. 좋아요와 로컬 플레이리스트 참조도 자동 삭제하지 않는다.

Drive의 명시적 삭제/접근 해제 또는 선택 파일의 404는 즉시 확정한다. 목록 비교만 가능한 Provider는 두 번의 정상 전체 조회에서 연속 누락된 경우에만 대기열 삭제를 확정한다. 실패·오래된 캐시·계정/선택 변경은 삭제 증거가 아니다.

## 자동 검증과 측정

`check-library-sync.cjs`는 가짜 시계·실제 Node SQLite로 주기·backoff·요청 공유·비활성 정리·원자적 쓰기 실패/취소·기존 페이지 호환·인증 정보 제외·대기열 보호를 검사한다. `check-library-sync-integration.cjs`는 실제 NAS 캐시/Query 실행기와 Drive Store/API 경로를 사용하고 HTTP·네이티브 경계만 모의한다.

동일한 가짜 시계에서 31초 간격 재진입 39회(19분 38초)를 실행하면 전체 NAS 조회는 기존 30초 정책의 39회에서 새 정책의 2회로 줄어든다. 기존 실서버 보관함의 16페이지를 가정하면 624→32 요청으로 환산된다. 이는 실제 변경 후 NAS에서 HTTP 요청을 측정한 결과가 아니다.

개발 빌드의 `[library-sync]` 로그는 Provider·요청 종류·시작 이유·시간·성공 여부만 기록한다. NAS `Song.list` 페이지와 전체 스캔을 구분하며, `libraryRequestStatistics()`로 최근 기록을 읽을 수 있다. 계정 주소·곡 제목·자격 증명·cursor는 로그에 넣지 않는다.

실 NAS의 추가/수정/삭제·인덱싱 중 목록 변경, Drive 실제 계정의 변경 피드·권한 해제, 실기기 네트워크 단절/복귀와 백그라운드 재생은 모의 테스트와 별도 항목이다. Windows에서 iOS 네이티브 빌드는 수행하지 않는다.

## 이번 실행 결과

- 타입 검사·ESLint 통과.
- 실행 가능한 회귀 스크립트 84개 통과. 새 스냅샷/동기화/실제 모듈 통합 검사와 NAS 인증 복원·재생 복원 회귀를 포함한다. 변경된 비동기 인증 준비 단계에 맞춰 기존 두 재생 테스트의 대기와 API 정보 fixture를 보완했다.
- Android Release `arm64-v8a` 빌드 성공. 기존 Gradle deprecation 안내는 남아 있다.
- iOS Hermes 번들 export 성공. iOS 네이티브 빌드·실기기 동작을 검증한 결과는 아니다.
- `check-clean-export.cjs`는 의존성·패치 변경이 없어 재설치 검증을 생략했고, `check-ios-lockscreen-artwork.cjs`의 네이티브 검증은 Windows 환경에서 실행하지 않았다.
- 최종 확인 시 ADB에 연결된 기기가 없어 새 APK 설치와 실제 NAS/Drive 동기화는 수행하지 못했다. APK는 `android/app/build/outputs/apk/release/app-release.apk`, 자동 검사·빌드 로그는 무시되는 `dist/library-sync/`에 있다.
